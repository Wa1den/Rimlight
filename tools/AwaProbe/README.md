# AwaProbe

Проверка контроллера на RP2040 с прошивкой
[HyperSerialPico](https://github.com/awawa-dev/HyperSerialPico) без основной программы.
Если лента не загорается, утилита отделяет неисправность железа или прошивки от ошибки в
том, что шлёт программа: с Rimlight в цепочке оба случая выглядят одинаково — тёмной лентой.

Прошивка принимает только протокол AWA — расширение Adalight с контрольной суммой. Стоковый
кадр `Ada` она отбрасывает на втором байте, поэтому Rimlight без поддержки AWA ленту не
зажжёт даже при правильной пайке.

## Прошивка

Файл `HyperSerialPico_rp2040_ws2812.uf2` из
[последнего релиза](https://github.com/awawa-dev/HyperSerialPico/releases/latest). Выход
данных — GPIO2, это умолчание сборки для обычных плат rp2040.

Плата переводится в режим загрузки кнопкой `BOOT`: зажать, воткнуть USB, отпустить. В
системе появится диск `RPI-RP2`, файл копируется на него, после чего плата перезагружается
сама и появляется как последовательный порт.

## Запуск

```
AwaProbe                     первый найденный RP2040, 122 диода, яркость 128
AwaProbe COM5 --leds 12      порт вручную, короткий отрезок ленты
AwaProbe --brightness 60     тусклее
AwaProbe --list              порты с идентификатором USB, RP2040 отмечен
AwaProbe --selftest          кодирование кадра против копии парсера прошивки
AwaProbe --auto              шаги по таймеру, без клавиш
```

Каждый шаг держится на ленте, пока не нажата клавиша: смотреть приходится на ленту за
монитором, и две секунды на цвет для этого мало. Esc прерывает проверку и гасит ленту. Если
ввод перенаправлен — из скрипта или другой программы, — шаги идут по таймеру сами. Запущенная
двойным щелчком утилита в конце ждёт клавишу, иначе окно закрылось бы вместе с результатом.

Порт не должен быть занят: Rimlight перед проверкой закрывается.

## Что происходит при проверке

1. **Приветствие.** Прошивка отвечает `Awa driver 11.` Ответ приходит до всякой ленты и
   подтверждает, что плата прошита и связь по USB есть. Нет ответа — дело в прошивке или в
   выборе порта, а не в пайке.
2. **Сплошные цвета** — красный, зелёный, синий, белый. Перепутанные красный и зелёный
   означают ленту с другим порядком цветов.
3. **Первый диод и бегущая точка.** Первый горит красным и должен оказаться у места пайки
   Din; затем зелёная точка бегает по ленте по кругу, пока не нажата клавиша. Точка,
   остановившаяся на полпути, указывает на обрыв данных после этого диода.
4. **Счётчики контроллера** за последнюю секунду: сколько кадров показано, принято, целых и
   битых. Битые кадры означают потерю байтов по USB.

## Почему DTR поднят

USB-стек прошивки читает данные только при поднятом DTR: `tud_cdc_connected()` в TinyUSB
проверяет именно этот сигнал. С опущенным DTR все байты молча отбрасываются. У Nano всё
наоборот — DTR перезагружает её в загрузчик, поэтому Rimlight держит его опущенным, и при
переходе на RP2040 это придётся различать.
